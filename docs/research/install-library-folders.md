# Install-target library folders — per-store evidence

This document records **what each storefront actually needs** when Windows Game Explorer creates an
install folder for it. It follows the same rule as the owned-games research: nothing is invented. A
store either has a verified folder layout (implemented) or gets a plain folder plus a note telling the
user which client dialog to point at it.

The implementation lives in `include/GameExplorerCore/InstallTargets.h` /
`src/core/InstallTargets.cpp` and is covered by `tests/TestInstallTargets.cpp`.

## Model

1. **One base folder**, set on the **Configuration** page (`installBaseFolder`, default
   `%USERPROFILE%\Game Explorer\Library`).
2. **One subfolder per storefront** beneath it (`Steam`, `GOG Games`, `Epic Games`, …).
3. **Only the files a storefront is verified to need** are created inside that subfolder.
4. The catalogue then opens the storefront's own install URI and asks the user to pick the folder it
   just created. The storefront client performs the install; Windows Game Explorer never downloads,
   unpacks or registers a game itself.

## Steam — verified

Steam calls an install location a *library folder*. Two files describe it, and both were inspected on
a Windows 11 machine with three libraries (`C:\Program Files (x86)\Steam`, `E:\Games\SteamLibrary`,
`D:\Games\SteamLibrary`).

**Client-owned registry** — `C:\Program Files (x86)\Steam\steamapps\libraryfolders.vdf` lists every
library with `path`, `label`, `contentid`, size tallies and an `apps` block. This file is Steam's own
bookkeeping: we never write it.

**Per-library marker** — every secondary library contains `libraryfolder.vdf` in its root. Observed
content (values differ per library):

```vdf
"libraryfolder"
{
	"contentid"		"7903621116869738055"
	"label"		""
	"launcher"		"C:\\Program Files (x86)\\Steam\\steam.exe"
}
```

What the catalogue creates for `<base>\Steam`:

```text
<base>\Steam\
├─ libraryfolder.vdf          (one marker, written once)
└─ steamapps\
   ├─ common\                 (installed games)
   ├─ downloading\            (Steam's staging area)
   └─ temp\                   (Steam's scratch area)
```

`libraryfolder.vdf` contains `"libraryfolder"`, a random **64-bit decimal** `contentid` and an empty
`label`. It is written only when missing: `contentid` is the library's identity, so rewriting it would
orphan an existing library.

Deliberately **not** created by us:

- **`launcher`** — Steam adds it itself when it registers the folder; our marker stays minimal.
- **`steamapps\libraryfolders.vdf`** — the client's registry, regenerated by Steam.
- **Per-game `appmanifest_<appid>.acf`** — produced by Steam during the actual install.

One user step remains: add the library once in **Steam → Settings → Storage → Add Drive**, then pick
it in Steam's install dialog. Steam then writes its registry and the per-game manifest.

## Epic Games Store — client-owned manifests, no marker

Epic keeps install records in its launcher data, not in the library folder:
`%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\*.item`, plus a per-game `.egstore` directory
created by the launcher. Adding a marker file would be invented state, so `<base>\Epic Games` receives
only the folder. The note tells the user to choose it in the launcher's install dialog.

## GOG GALAXY — client-owned database, no marker

GOG GALAXY stores its library in its own storage under `%ProgramData%\GOG.com\Galaxy`. A GOG install
folder carries no marker that we can verify, so `<base>\GOG Games` receives only the folder and a note.

## itch.io — app-owned library locations, no marker

The itch app manages its own library locations in its configuration. The catalogue creates
`<base>\itch.io` and tells the user to point the itch app's install location at it; the app records
the rest.

## Xbox / Microsoft Store — cannot be redirected

MSIX/Store packages install into the per-volume, ACL-protected `WindowsApps` folder managed by
Windows. A custom folder cannot be used, so the catalogue says so instead of creating a folder that
could never receive the game. (Drive selection is a Windows setting, not a per-app one.)

## Unknown or future storefronts

Fallback: `<base>\<store key>` with no marker and a note that the store's own client decides what the
folder needs. This keeps the feature usable without encoding guesses.

## Rejected approaches (would be guesswork)

- Inventing marker files (`.gog-library`, `epic-library.json`, …) — no client reads them, and a stray
  file could confuse a future client version.
- Pre-creating per-game manifests (`.acf`, `.item`) — these embed install state only the client can
  produce correctly, including checksums and timestamps.
- Moving installed games by editing storefront manifests by hand — the catalogue does not rewrite
  proprietary state.
- Installing from the catalogue itself — ownership and install integrity stay with the storefront.

## Sources

**Primary evidence (inspected on 2026-10-25):**

- `C:\Program Files (x86)\Steam\steamapps\libraryfolders.vdf` — library registry format.
- `E:\Games\SteamLibrary\libraryfolder.vdf`, `D:\Games\SteamLibrary\libraryfolder.vdf` — per-library
  marker format and `contentid` shape.
- `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\` — Epic install-record location.
- `%ProgramData%\GOG.com\Galaxy` — GOG GALAXY storage location.
